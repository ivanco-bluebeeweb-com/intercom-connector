# Intercom Connector — заметка по аутентификации (OAuth)

Дата анализа: 2026-08-31

## Коротко: OAuth НЕ используется — Access Token приватного приложения

Intercom поддерживает OAuth2 только для публичных приложений из их
App Store. Для работы со СВОИМ workspace правильный путь — **private app
Access Token** из Developer Hub. Коннектор работает именно так:
пользователь создаёт приватное приложение и вставляет его токен.

## Как устроено подключение

1. Пользователь открывает **Developer Hub** в своём Intercom workspace
   → New app → видит **Access Token** сразу;
2. В панели Imperal вводит этот токен в `connect_intercom` — коннектор
   проверяет его до сохранения.

## Что автоматизировано, а что — руками

| Этап | Как делается |
|---|---|
| Создание приватного приложения | **РУКАМИ** — Intercom Developer Hub (одноразово) |
| Копирование Access Token | **РУКАМИ** — показывается сразу при создании приложения |
| Валидация токена при подключении | **АВТОМАТИЧЕСКИ** |

## Почему не браузерный OAuth

OAuth2 Intercom нужен приложениям, которые подключаются к ЧУЖИМ workspace
(публичная витрина). Наш коннектор управляет СОБСТВЕННЫМ workspace
пользователя — для этого приватный Access Token и предназначен, он не
протухает и не требует браузера.

## Следствие для тестирования

Полный тест (контакты, компании, разговоры, тикеты, статьи, Fin) требует
Access Token реального Intercom workspace. Получение — минутное ручное
действие владельца workspace.
